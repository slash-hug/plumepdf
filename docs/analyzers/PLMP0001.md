# PLMP0001 — composed document is never rendered or saved

**Analyzer:** `PlumePdf.Analyzers.ManuscriptNeverRenderedAnalyzer` (`analyzers/PlumePdf.Analyzers/`), shipped inside the `PlumePdf` NuGet package as a build-time-only analyzer assembly under `analyzers/dotnet/cs/` — one runtime assembly, one build-time analyzer assembly, one package.

**Severity:** Warning.

**Cause:** A local variable is initialized from `new Manuscript { ... }` and the method never calls `.Render(...)` on it, **or** a local variable is initialized from `PdfDocument.Compose(...)` and the method never calls `.Save(...)`/`.SaveIncremental(...)` on it. In both shapes the caller paid the cost of building a document in memory and produced no output — almost always a forgotten call, not an intentional no-op.

The analyzer is deliberately conservative: a tracked local that is `return`ed from the method, passed as an argument to another method or constructor, or assigned to anything other than itself (a field, a property, ...) is treated as having escaped analysis (the callee, or whatever holds the assigned-to location, may be the one that renders or saves it) and is never flagged.

**Example (flagged):**

```csharp
// Manuscript form — built, never rendered:
var invoice = new Manuscript
{
    Sections = [new Section { /* ... */ }],
};
// missing: invoice.Render(...)

// Compose form — built, never saved:
var doc = PdfDocument.Compose(page =>
{
    page.Content().Text("Hello, world!");
});
// missing: doc.Save("out.pdf")
```

**Fix:** Call `Render(...)` on the constructed `Manuscript` (or pass it to code that will), or call `Save(...)`/`SaveIncremental(...)` on the `PdfDocument` returned by `Compose(...)`:

```csharp
var invoice = new Manuscript
{
    Sections = [new Section { /* ... */ }],
};
using var document = invoice.Render();
document.Save("invoice.pdf");

using var doc = PdfDocument.Compose(page =>
{
    page.Content().Text("Hello, world!");
});
doc.Save("out.pdf");
```

**Recovery attempted:** None — this is a build-time diagnostic on caller code, not a runtime failure PlumePdf itself encounters.
