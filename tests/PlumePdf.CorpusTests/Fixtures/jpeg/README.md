# JPEG hermetic fixtures

Committed once, frozen thereafter — never regenerated by CI or by fetch-corpora.sh (which
stays fetch-only). Each `.jpg` below was generated locally with libjpeg-turbo's `cjpeg`
(the same tool `DjpegInteropTests`/`generate-codec-fixtures.sh`'s live lane exercises
against PlumePDF's own decoder) from a synthetic source image, never a real photograph, so
provenance and license are unambiguous.

Tool: `cjpeg` (libjpeg-turbo 3.2.0, Homebrew build), 2026-08-20.
Source images: a synthetic 64x48 RGB gradient (`test.ppm`) and a synthetic 37x29 RGB
pseudo-noise pattern (`test_odd.ppm`, chosen odd/non-MCU-aligned to exercise edge padding
and cropping), both generated by a throwaway script, not committed.

| File | Command |
|---|---|
| `baseline-420-q90.jpg` | `cjpeg -quality 90 -sample 2x2 -outfile … test.ppm` |
| `baseline-444-q90.jpg` | `cjpeg -quality 90 -sample 1x1 -outfile … test.ppm` |
| `grayscale-q90.jpg` | `cjpeg -quality 90 -grayscale -outfile … test.ppm` |
| `progressive-420-q90.jpg` | `cjpeg -quality 90 -progressive -sample 2x2 -outfile … test.ppm` |
| `progressive-444-q90.jpg` | `cjpeg -quality 90 -progressive -sample 1x1 -outfile … test.ppm` |
| `restart-420-q85.jpg` | `cjpeg -quality 85 -sample 2x2 -restart 2 -outfile … test.ppm` |
| `odd-dims-420-q80.jpg` | `cjpeg -quality 80 -sample 2x2 -outfile … test_odd.ppm` |
| `odd-dims-444-q80.jpg` | `cjpeg -quality 80 -sample 1x1 -outfile … test_odd.ppm` |
| `odd-dims-progressive-420-q80.jpg` | `cjpeg -quality 80 -progressive -sample 2x2 -outfile … test_odd.ppm` |
| `corrupt-truncated-header.jpg` | First 40 bytes of `baseline-420-q90.jpg` — cut before `SOF0`; undecodable from the start (throws, does not degrade). |
| `corrupt-truncated-scan.jpg` | First 629 bytes of `baseline-420-q90.jpg` — a complete header but `SOS`'s entropy-coded data cut 20 bytes in; decode-as-far-as-possible (partial result + diagnostic, does not throw). |

`cmyk-flat-adobe.jpg` is not listed here: no CLI tool in this environment can author a
genuine CMYK JPEG (`cjpeg` accepts only grayscale/RGB PPM input), so it is generated
in-process at test time by `CmykJpegFixture` (`tests/PlumePdf.Tests/Filters/Jpeg/`) from
`JpegFdct`/`JpegHuffmanTable` directly rather than committed as bytes — see that file's
remarks.
